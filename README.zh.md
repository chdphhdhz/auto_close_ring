# 关闭页面_定时

[English README](README.md)

这是一个 Chrome / Microsoft Edge 浏览器扩展，基于 Manifest V3。扩展用于自动处理指定域名页面：在页面右上角显示倒计时，并在随机秒数后关闭标签页；如果页面中出现指定的保护 iframe，则取消关闭逻辑、播放提示音，并清理相关 `Auto Open` 页面中的定时器。

当前默认目标域名是 `h5.ele.me`，默认保护 iframe 选择器是 `#baxia-dialog-content`。

## 主要功能

- 支持 Chrome 和 Microsoft Edge。
- 支持配置一个或多个目标域名。
- 支持配置随机关闭时间范围，默认 `8` 到 `12` 秒。
- 在目标页面右上角注入倒计时提示框。
- 在目标页面注入「停止插件」按钮，可直接从网页中停止扩展。
- 在目标页面和标题以 `Auto Open` 开头的页面注入「暂停打开」按钮。
- 检测到保护 iframe 后，不关闭当前页面，并播放提示音。
- 检测到保护 iframe 后，会尝试清理所有 `Auto Open` 页面的 timeout 和 interval，暂停相关页面继续自动打开新页面。
- 弹窗页支持配置目标域名、关闭时间范围和保护 iframe CSS 选择器。

## 安装方式

### Chrome

1. 打开 Chrome。
2. 访问 `chrome://extensions/`。
3. 打开右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」。
5. 选择本项目目录。
6. 安装完成后，浏览器工具栏会出现扩展图标。

### Microsoft Edge

1. 打开 Microsoft Edge。
2. 访问 `edge://extensions/`。
3. 打开「开发人员模式」。
4. 点击「加载解压缩的扩展」。
5. 选择本项目目录。
6. 安装完成后，浏览器工具栏会出现扩展图标。

## 使用方法

1. 点击浏览器工具栏里的扩展图标。
2. 在「目标域名」中填写需要自动处理的网站域名。
   - 示例：`h5.ele.me`
   - 多个域名用英文逗号分隔，例如：`h5.ele.me,example.com`
3. 在「关闭时间范围（秒）」中填写最小秒数和最大秒数。
   - 扩展会为每个目标页面随机选择一个关闭时间。
   - 例如 `8` 和 `12` 表示页面会在 8 到 12 秒之间随机关闭。
4. 在「保护 iframe 选择器」中填写用于保护页面的 CSS 选择器。
   - 默认值：`#baxia-dialog-content`
   - 检测到该选择器对应的元素时，扩展会取消关闭当前页面并播放提示音。
5. 点击「启动」。
6. 打开或刷新目标域名页面，页面右上角会出现倒计时。
7. 需要停止时，可以点击弹窗里的「停止」，也可以点击网页右上角的「停止插件」。

## 页面注入元素

| 元素 | 说明 |
| --- | --- |
| 「停止插件」 | 停止整个扩展的自动关闭逻辑，并清理当前扩展维护的标签页定时器。 |
| 「暂停打开」 | 清理标题以 `Auto Open` 开头页面中的 timeout 和 interval。 |
| 「将关闭：N秒」 | 当前目标页面的关闭倒计时。 |

## 默认配置

默认配置定义在 `background.js` 的 `DEFAULT_CONFIG` 中：

```js
{
    targetDomains: ["h5.ele.me"],
    minTime: 8,
    maxTime: 12,
    protectedIframe: "#baxia-dialog-content"
}
```

弹窗页会把配置保存到 `chrome.storage.local`。下次打开弹窗时，会读取已保存的目标域名、关闭时间范围和保护 iframe 选择器。

## 配置清洗规则

后台会通过 `sanitizeConfig` 规整配置：

- 域名会转为小写。
- 域名会去掉协议、路径、端口、通配前缀和多余点号。
- 多个目标域名会自动去重。
- `minTime` 和 `maxTime` 必须是正整数。
- 如果最小秒数大于最大秒数，会自动交换。
- 没有有效目标域名时，会回退到默认域名 `h5.ele.me`。
- `protectedIframe` 为空时，会回退到默认值 `#baxia-dialog-content`。

## 核心流程

### 启动

点击弹窗「启动」后，`popup.js` 会先保存配置，再向后台发送 `{ type: "start" }`。

后台 `background.js` 会：

- 设置运行状态为 `true`。
- 保存运行状态到 `chrome.storage.local`。
- 切换运行图标和徽标文字。
- 启动全局 iframe 告警检测。
- 扫描所有已经打开的标签页。

### 停止

点击弹窗「停止」或页面里的「停止插件」后，后台会：

- 设置运行状态为 `false`。
- 切换停止图标和徽标文字。
- 停止全局 iframe 告警检测。
- 清理每个标签页的关闭定时器和 iframe 检测定时器。
- 移除页面里的「停止插件」按钮。
- 保留页面里的「暂停打开」按钮。

### 目标页面处理

`processTab(tabId, tab)` 是主要标签页处理函数。

处理逻辑：

- 如果页面 host 匹配目标域名，注入「停止插件」和「暂停打开」按钮。
- 如果页面标题以 `Auto Open` 开头，注入「暂停打开」按钮。
- 只有目标域名页面会检测保护 iframe。
- 如果检测到保护 iframe：
  - 取消关闭当前页面。
  - 播放提示音。
  - 清理所有 `Auto Open` 页面中的定时器。
- 如果没有检测到保护 iframe：
  - 按配置的 `minTime` 到 `maxTime` 随机生成倒计时。
  - 页面右上角显示 `将关闭：N秒`。
  - 倒计时结束后关闭当前标签页。
  - 倒计时期间每秒重新检测保护 iframe，若中途出现则取消关闭并告警。

## Auto Open 页面

项目把标题以 `Auto Open` 开头的标签页视为自动打开页面。

点击「暂停打开」按钮，或在目标页面检测到保护 iframe 后，后台会遍历所有标签页，对 `Auto Open` 页面注入脚本并循环清理页面里的 timeout 和 interval：

```js
for (let i = 0; i < 65536; i++) {
    clearTimeout(i);
    clearInterval(i);
}
```

这个逻辑用于暂停相关页面继续自动打开新页面。

## 修改代码后如何生效

本项目没有 `package.json`，没有构建步骤，也不需要安装 npm 依赖。

修改代码后：

1. 打开 `chrome://extensions/` 或 `edge://extensions/`。
2. 找到「关闭页面_定时」。
3. 点击刷新 / 重新加载按钮。
4. 重新打开或刷新目标网页。

## 常见问题

### 为什么页面没有倒计时？

请检查：

- 是否已经点击弹窗里的「启动」。
- 当前页面域名是否匹配「目标域名」。
- 当前页面是否已经加载完成。
- 当前页面是否是浏览器内置页面，例如 `chrome://` 或 `edge://`，这类页面通常不能注入脚本。
- 修改代码后是否已经在扩展管理页重新加载扩展。

### 为什么页面没有自动关闭？

可能原因：

- 页面中检测到了保护 iframe，扩展会取消关闭该页面。
- 当前页面不属于目标域名。
- 浏览器限制了脚本注入。
- 扩展已经被手动停止。

### 为什么重新打开浏览器后不是运行中？

当前 `background.js` 初始化时会读取已保存配置，但会强制把 `isRunning` 设为 `false`。也就是说，扩展不会自动沿用上一次的运行状态，需要重新点击「启动」。

### 为什么需要这些权限？

扩展需要：

- `tabs`：扫描、识别和关闭标签页。
- `storage`：保存配置和运行状态。
- `scripting`：向目标页面注入倒计时、按钮、检测和提示音脚本。
- `background`：配合后台 service worker 运行。
- `<all_urls>`：允许扩展在用户配置的不同网站上工作。

## 维护提示

- 当前实际入口是 `background.js`，不是历史备份文件。
- 修改后台逻辑后，需要重新加载扩展。
- `background.js` 是 Manifest V3 service worker，不要假设它会像普通页面一样长期常驻。
- 页面注入可能因为特殊页面、浏览器内置页面或权限限制失败，当前代码多数地方会静默忽略失败。
- 修改目标域名匹配逻辑时，优先保留 `normalizeDomain`、`sanitizeConfig` 和 `isTargetHost` 的组合。
- 修改关闭逻辑时，要同时考虑 `closeTimer`、`checkInterval` 和 `alertOnly` 三类状态。
- 修改页面注入 UI 时，注意「停止插件」「暂停打开」和倒计时框不要相互重叠。
- 修改保护 iframe 配置链路时，需要同步检查 `background.js`、`popup.html` 和 `popup.js`。
- 项目文件应按 UTF-8 读取和保存，避免中文注释和界面文案出现乱码。
